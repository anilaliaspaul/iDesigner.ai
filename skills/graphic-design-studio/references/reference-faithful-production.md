# Reference-faithful production and asset integrity

When a user supplies a reference and asks to use it, match its visual language and composition deliberately. Do not silently replace it with the plugin's default minimalist aesthetic.

## Classify the reference
Identify whether each image is a style reference, composition reference, exact asset source or content reference. If the user says "same style", "like this", or asks to replace a subject while retaining the poster, treat the reference as a design specification. Record what stays, what changes and what is locked.

## Asset provenance
Record the exact source path for every required asset. Use the exact approved logo, church exterior, Saint/person image and other supplied assets. Never substitute an AI-generated lookalike.

### Logo lock
Place the exact approved logo file as an image asset. Preserve original artwork, lettering, colours, transparency and proportions. Only uniform scaling and positioning are permitted. Never redraw, trace, retype, recolour, distort, crop destructively, stylize or regenerate it. Do not add an oval, white rectangle, badge or backing unless the reference shows it or contrast truly requires it.

### Exact subject lock
Use the exact supplied church image and preserve roof profile, cross, facade, windows, doors, materials and proportions. Use the exact Saint image and preserve face, halo, vestments, hands, censer and iconography. Never ask image generation to recreate them.

## Integration, not cut-and-paste
A raw cutout placed over a background is not a finished composite. Do not use crude polygons, destructive white-pixel thresholds, white boxes, oval frames or sticker edges.

Use high-quality segmentation/matting and edge refinement. Preserve fine details such as halo filigree, hair, smoke, chains, white robes, foliage and roof edges. Inspect mattes over light and dark backgrounds. If a clean extraction is impossible, retain the full source in an intentionally designed photo frame/window or atmospheric fade; ask for a transparent source if necessary.

Integrate with motivated lighting, colour temperature, contrast, scale, perspective, depth, contact shadow, ambient occlusion and foreground/background overlap. Do not warp architecture or people. Avoid generic glow outlines and aggressive filters.

## Typography follows the reference
If a reference is supplied and the user asks to follow its style, its display typography takes precedence over brand-kit display-font defaults for titles, festival names, anniversary numerals and ribbons. Use the exact font if known and available. If unknown or custom, identify its visible traits and reproduce the style using the closest suitable font plus deliberate editable/vector effects (gradient, bevel, outline, extrusion, shadow, ornament). Brand fonts remain appropriate for supporting copy and for designs without reference typography. Never silently substitute a plain default font.

Keep Malayalam text exact, editable and correctly shaped. Never generate text in an image model.

## Image generation boundaries
Generate supporting atmosphere/backgrounds only. Do not generate logos, church names, exact church architecture, exact Saint imagery, dates, badges or other exact supplied assets. Never generate a complete poster and then cover fake generated elements with the real assets. Build the composition around the real assets from the start.

## Reference-fidelity review
Before presentation, compare side-by-side with the reference: composition, hierarchy, typography, palette, texture, ornaments, image scale, depth, overlap and lighting. A design that merely contains the requested items but does not resemble the reference has not fulfilled the brief.
